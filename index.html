How Atlas chooses a status

  1. Identify the order. Start with the OrderWise (OW) Sales Activity spreadsheet. Match the order number, order reference or tracking ID required by the platform.
  2. Read the named source. The steps below identify the API or spreadsheet, the match field and the status field. Tracking shows the source label where available. All Methods uses the shared Atlas status.
  3. Follow the fallback. If the platform has no usable result, follow its fallback steps. OW order status comes from Sales Activity column J.

Yellow marks proposed application changes.

Platform Statuses

OptimoRoute

Source and decision order

  1. Spreadsheet — Own van override. Look for the OW order number in Routine Dashboard - Live. A recognised colour override takes priority for Own van: white or amber gives Scheduled, and yellow gives Failed.
  2. API — OptimoRoute. If there is no override, match Sales Activity column E (Order reference) to a unique OptimoRoute API data.orderNo and read the provider status. For example, scheduled, on_route and servicing go to Out for Delivery. If no usable match or mapping is available, go to step 3.
  3. Spreadsheet — OrderWise fallback. Use Sales Activity column T (Delivery method) for method rules and column J (Status) for the order-status fallback. The yellow overview entries for rejected, cancelled and returned describe proposed changes.

Palletways

Source and decision order

  1. Spreadsheet — Tracking label and identifiers. Match Sales Activity A (Order no) to Palletways A (Customer Ref). Palletways B is Tracking ID, C is Consignment Number, F is the Tracking label, and Z/AA are booking fields. These sheet values are separate from the API delivery evidence.
  2. API — Delivery classification. Atlas currently checks stored Palletways API history by an 11-digit tracking number from the delivery record. If there is no valid number, it can match the stored API Reference to the OW order number. Read the matched consignment and event history for movement, delivery or POD evidence. The 3 Days monitor separately checks Palletways B before other tracking fields.
  3. Spreadsheet — If API evidence is missing. Atlas currently falls back to OW Sales Activity J (Status), so OW Completed can appear as Delivered. The proposed rule requires confirmed Palletways API evidence before classifying Delivered or JOB COMPLETE as delivered. Keep the sheet F label for Tracking when available.

Amazon Shipping

Source and decision order

  1. Spreadsheets — Match the shipment. Match OW Sales Activity S (Tracking No) to Amazon Shipping B (Tracking ID). Read Amazon Shipping G (Order status). The Atlas status sync reads this worksheet.
  2. Spreadsheet — Display and classify. Keep the Amazon G label in Tracking. When the value has a mapping, use it for the All Methods classification. For example, IN_TRANSIT maps to Scheduled and DELIVERED maps to Delivered.
  3. Spreadsheet — If G is unavailable or unmapped. Check whether OW S is blank, then apply the applicable OW method (T) or status (J) fallback. The proposed rule leaves delivery unconfirmed when the only evidence is OW Completed. The yellow overview proposes REJECTED → Failed and RETURNED_TO_SELLER → Cancelled, while the detail rows still say Rejected and OW fallback respectively. The All Methods rule needs confirmation.

XDP

Source and decision order

  1. Spreadsheet — Current Tracking label. Match the order or tracking identifier in the XDP tab. Use column I (Latest Status) and J (Latest Detail). Atlas currently maps DAMAGE, DELETE and NOT RECEIVED to Failed and otherwise keeps the XDP label separate from its shared classification.
  2. Spreadsheet — Current event history. XDP Activity B identifies the order. Atlas imports the event history from the XML stored in column M, with column I as a status type input. The proposed rules below refer to the event type and detail represented by I (Status Type) and J (Status Data).
  3. Proposed gate — Determine progress per consignment. Read the newest substantive event first. Skip SMS and EMAIL. Use the event type and detail together. If the event does not establish progress, look back for the latest usable event. Use Awaiting if there is none. Classify the order as Delivered once every consignment is delivered.

StopStart

Source and decision order

  1. Spreadsheet — Match the order and read Tracking. Match the OW order number to STOPSTART A and read STOPSTART I (Tracking status). Atlas reads this worksheet for these labels.
  2. Spreadsheet — Check the carrier result. The proposed rule updates the same order to Delivered when STOPSTART I reports Delivered. Past Expected Date — Unconfirmed stays unconfirmed. Expected Today qualifies for the existing Today check, subject to its exclusions.
  3. Spreadsheet — Apply the OW fallback. If STOPSTART I is blank or tracking is unavailable, use OW Sales Activity J for other applicable classifications. Under the proposed rule, OW Completed alone leaves delivery unconfirmed.

  1. Spreadsheet · STOPSTART A and I Check STOPSTART A for the order and I for the tracking label.
  2. Spreadsheet · OW Sales Activity J Use OW J for other applicable classifications. OW Completed leaves delivery unconfirmed.
Expected TodayThe source expects delivery today. This label qualifies for the Today filter, subject to its exclusions.
  1. Spreadsheet · STOPSTART A and I Check STOPSTART A and I. Apply the Today filter exclusions.
  2. Spreadsheet · OW Sales Activity J Use OW J for other applicable classifications. OW Completed leaves delivery unconfirmed.

  2. Spreadsheet · STOPSTART I Classify as Delivered when column I reports Delivered. Past Expected Date — Unconfirmed leaves delivery unconfirmed.
  3. Spreadsheet · STOPSTART I + Spreadsheet · OW Sales Activity J If column I is blank or tracking is unavailable, use OW column J for other applicable classifications. OW Completed alone leaves delivery unconfirmed.
Past Expected Date — UnconfirmedThe expected delivery date has passed without delivery confirmation.
  1. Spreadsheet · STOPSTART A and I Check STOPSTART A and I. Keep delivery unconfirmed.
  2. Spreadsheet · STOPSTART I + Spreadsheet · OW Sales Activity J Use OW J for other applicable classifications. Update the same order if STOPSTART later reports Delivered.
